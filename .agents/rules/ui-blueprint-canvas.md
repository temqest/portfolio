# Rule: Technical Blueprint & Kinetic Canvas Fidelity

When authoring canvas-rendered technical blueprints, architectural illustrations, or particle schematics:

1. **Domain-Specific Architecture Over Copied Chrome**:
   - Reference images demonstrate the **medium standard** (particle density, jitter envelope, line weight, solid accent contrast, scale), **NOT** a template to replicate indiscriminately across disciplines.
   - **Never inject decorative top chrome (e.g. filter pills, status circles, navigation buttons)** onto engineering diagrams where they do not belong (e.g. database cylinders, security locks, radar scopes, distributed network graphs, velocity dials).
   - Each discipline must visually express its own functional reality (e.g., local SQLite commit layers, cryptographic shackle cores, radar azimuth rings, micro-service constellations, transient waveforms).

2. **Spacious Geometry & True Centering**:
   - Technical diagrams must be vertically and horizontally centered with balanced negative space.
   - Avoid squishing graphics downwards or compressing proportions to fit arbitrary auxiliary decorations.

3. **High-Contrast Stippled Textures**:
   - Contrast dark charcoal linework (`#0a0f1d`) against dense, solid-filled cobalt accent zones (`#2f5ce8`) and crisp white negative-space cutouts (such as checkmarks, keyholes, crosshairs).
   - Use zero-GC typed array buffers for 60fps morph transitions between distinct topologies.
